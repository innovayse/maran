# Threat note: return the panel to a self-signed certificate on request (issue #425)

`rules/security.md` requires a threat note, written first, for a change that adds an agent rpc
which writes a TLS key as root. This change lets an administrator replace the panel's trusted
certificate with a self-signed pair again (follow-up of #132, whose note is
`2026-11-01-panel-certificate-threat-note.md`). It is written before any code of the branch.

**The second reviewer requirement is OUTSTANDING.** The work is carried out by an agent session,
which cannot obtain one. This branch MUST NOT merge to `main` until a human reviewer has read it
and signed off; it merges to `dev` only. Recorded together with the other outstanding reviews
under #331.

## The surfaces this change adds

1. **One new rpc on `SslService`**: `RestorePanelSelfSigned(host_name)` in
   `proto/agent/v1/ssl.proto`. It generates a self-signed pair and replaces the pair the panel
   vhost names (`/etc/maran/tls/panel.crt`, `panel.key`) through the same write path as
   `InstallPanelCertificate`.
2. **An HTTP endpoint, administrators only**: `DELETE /api/v1/panel-certificate`, journalled, and
   a button on the panel certificate page behind a confirmation.
3. **A database change that only deletes a row**: the recorded `PanelCertificate` row for the
   host name is removed after the agent succeeded, so the renewal sweep stops renewing a
   certificate that is no longer installed. No schema change.

## What an attacker could do with each, and why it is safe

**Who can reach the rpc.** Only `maran-api` (peer-credential check on the agent's socket,
unchanged), and inside the panel only the Ssl module, which already declares the Ssl capability.
The endpoint is `AuthorizationPolicies.AdminOnly`; a customer cannot call it and gets no
signal about it.

**What the rpc takes.** One string, the host name. The agent parses it into the validated
`Domain` type before anything is generated, so no comma, slash, equals sign, newline or control
character can reach the `-subj` or `-addext` value openssl parses. The backend sends the
operator's own `Panel__HostName`; it is never taken from the request.

**Downgrade as an attack.** The effect is an availability and trust downgrade: browsers warn
until a trusted certificate is installed again. An attacker who can call it already holds an
administrator session, which can equally install any certificate through the #132 endpoint, so
the endpoint grants nothing new. The action is journalled (`panel.certificate.restore_self_signed`),
the agent's mutating-rpc audit line records it, and the SPA asks for confirmation naming the
consequence.

**Losing a good certificate by mistake.** The previous trusted pair is overwritten and not kept.
That is the request: the operator asked to leave it. Ordering a new certificate again is one
click. A failed write, an nginx refusal or a failed reload restores the previous pair, so a
failure leaves the panel serving what it served.

**Key generation.** The key is generated by the agent's existing `generate_material`
(openssl, RSA 2048, ten years), never logged, written 0600 root before the rename, `Debug` of the
material prints `<redacted>`.

**Idempotence.** Calling it while a placeholder is already installed regenerates one. It is a
replacement, not an error and not a no-op, because the host name may have changed.

## What a reviewer must check

- `agent/crates/ops/src/ssl/restore_panel_self_signed.rs`: the host name is a `Domain`, the pair
  is written as one `write_config_set`, rollback on every refusal, marker written after the bytes.
- The service wrapper audits the call as mutating (`audit/mutating_rpcs.rs`).
- `DELETE /api/v1/panel-certificate` is `AdminOnly`, journalled, and deletes the row only after
  the agent answered success.

## What the author could not verify

- Behaviour on a real host with nginx 1.20.1 and 1.24.0: covered only by the polygon suite of
  #132 once it runs in CI.
- That a browser session open on the panel survives the reload; nginx reloads gracefully and the
  session is cookie-based, but it was not observed.
